### Microweber API and security baseline (2026-10-03)

- The [official REST API guide](https://github.com/microweber/microweber-docs/blob/master/guides/rest_api.md) describes public, admin-only, and logged-in-user endpoint registration, and explicitly warns that its enumerated endpoint list can change; the deployed `/api/api_index` is the runtime inventory. It lists broad content/import and commerce operations, not a versioned Titan renderer contract. Do not call arbitrary endpoint names or treat the list as a stable compatibility guarantee.
- The official [Microweber disclosure issue #1180](https://github.com/microweber/microweber/issues/1180) is still open and says a full disclosure was sent privately; it has no assigned maintainer, label, fix branch, or linked PR in the issue view. A separate unreviewed advisory alleges stored XSS in tag handling through `save_content_admin` up to v2.0.20 ([GHSA-793c-7c93-m769](https://github.com/advisories/ghsa-793c-7c93-m769)); this allegation is not independently verified here and is not treated as a confirmed vendor finding.
- The [official releases page](https://github.com/microweber/microweber/releases) currently lists v2.0.20 as latest. No patched/approved version or fixed API contract has been identified. Before a live adapter can be accepted, pin a vendor-supported release and prove the disclosure's status/remediation (or obtain maintainer security disposition), then test the exact admin API/method/CSRF behavior against that version. The current code intentionally stops at a declarative, authority-free handoff; it does not call Microweber.

### Governed module presentation slice (2026-10-03)

`createBrandModulePresentation` now maps the issue's 18 `titan/*` module families to the existing Titan Interface Runtime presentation tree/v2 context and Interaction Engine governed presentation-intent contract. Canonical callers supply the resolved capability ID, company-bound opaque data/evidence references, and `BrandActionBinding` descriptors. Company/context/reference mismatch, unsupported modules, mismatched action capabilities, missing required context, malformed IDs, and over-limit actions fail closed. If the capability is absent from the trusted context, the presentation and Interaction intent contain only an unavailable fallback with no data/evidence references or actions. The tree, actions, and every node remain authority-neutral.

This is a declarative presentation seam only: it does not resolve entitlements, fetch domain records, render Microweber modules, invoke actions, produce receipts, or prove action-to-evidence continuity. The #1060 channel/provider contracts and canonical domain/Interaction/ExecutionGateway owners still need integration, and the module-specific UX, guest privacy, offline behavior, responsive/accessibility behavior, and end-to-end tests remain incomplete. Do not describe the module bridge as an executable Titan component integration.
