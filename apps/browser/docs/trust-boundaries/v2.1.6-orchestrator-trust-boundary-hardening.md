# Codee v2.1.6 Orchestrator Trust-Boundary Hardening

This release rebases the deeper adversarial trust-boundary audit onto v2.1.5. Titan Zero Developer Intelligence, Repository/Coding Intelligence, and the 14-manager AI Workforce remain integrated. Codee core remains the only plan-advance authority.

## 1. Artifact Receipt Authority

New plans use both:

- `artifactVerificationMode: receipt_required`
- `artifactValidationMode: strict_v216`

A model footer is evidence, not authority. Advancement requires a host/MCP-generated receipt proving the reported ZIP exists, download completed, actual bytes match the footer SHA-256 and size, ZIP integrity passes, and the ZIP content manifest was verified. Strict receipts also require a non-empty entry count, a 64-hex content-manifest SHA-256, and a host-supplied valid verification timestamp.

Strict footer metadata validates artifact ID, basename-only ZIP, allowlisted type, version, ZIP/DELTA sizes, files changed, ISO timestamp, parent chain, protocol/run/step/token identity, status, action and verification status.

## 2. Command Security Rewrite

The canonical command policy uses:

- `READ`
- `VERIFY`
- `EXECUTE`
- `WRITE`
- `DESTRUCTIVE`
- `UNKNOWN` / `INVALID` fail closed

Project test runners are `EXECUTE`, not `READ`. Bounded syntax checks such as `php -l` and `node --check` are `VERIFY`. Path-bearing command arguments are validated against repository scope. Shell chaining/redirection is rejected by the safe channel.

Caller metadata is nested under `meta`; it cannot override Codee-owned scope, classification, read-only state, effects or targets.

## 3. Complete Backup Effects

Mutating/executing command envelopes carry effect manifests and required backup domains. Examples:

- Laravel migrations / seeders → `database`
- cache/config/route/view caches → `runtime` + `generated_state`
- storage links / file generators → `repository` + `filesystem`
- dependency install/update → `repository` + `generated_state`
- project test/script execution → `repository` + `database` + `runtime` + `external`
- Git mutation → `git` + `repository`
- Git push → also `git_remote`

The privileged host must prove coverage of every required domain (or a verified full-scope backup) before approval/execution. Missing/incomplete effects block execution.

## 4. Governed MCP Gateway

Every tool call is classified locally before transport. Remote metadata may escalate risk but cannot downgrade clear Codee-local write/execute/destructive semantics. Unknown tools cannot become `READ` just because the remote server says they are read-only.

Mutating MCP calls require:

1. prepare exact effects/targets
2. merge Codee-local backup-domain floors
3. create backup
4. verify backup identity, checksum and complete domain coverage
5. approval
6. execute
7. verify mutation
8. durable audit receipt
9. retain rollback metadata

MCP evidence gathering permits only governed READ tools. Direct MCP arguments/results are structurally bounded and secret-redacted before transport/serialization.

## 5. Positive Prompt Acknowledgement

Composer clearing is not submission proof. Codee records acceptance only after a provider-rendered **new user-message node** contains the exact current `STEP_TOKEN` (legacy no-token flows require matching newly rendered prompt text).

Authoritative submission evidence is stored in extension-owned plan state as a durable `submissionReceipt`. Provider page `sessionStorage`/`localStorage` is not used for Codee control-plane idempotency.

## 6. Conversation Identity v3

ChatGPT/Claude new-chat pages use provisional identities and one-way promotion to structured conversation IDs. The saved worker identity remains authoritative across root-page/content-script reloads.

One active plan owns one conversation identity regardless of browser tab. Same-plan duplication in a second tab is also rejected. Tab-ID reuse preserves the previous plan under an orphan key rather than overwriting it. Provisional-to-structured promotion checks for an existing conversation owner and fails closed on collision.

## 7. Retry and Resource Controls

- automatic logical model retries: 2
- transient delivery retries: 5
- explicit backoff/cooldown state
- retry budget exhaustion → blocked / needs user
- per-step text limit: 120,000 characters
- final dispatch prompt limit: 200,000 characters
- plan total remains bounded
- ignored/generated repository files are filtered before analyzed-file count limits
- Repository/Titan analyzed-file ceiling increased to 12,000 after filtering
- MCP response/argument structures are bounded before JSON serialization
- artifact footer parsing and detector caches remain bounded

For very large repositories, the intended host/MCP path is inventory/index → select relevant files → send only selected source evidence rather than one unbounded browser message.

## 8. Audit, Storage, Scope and Provider Cleanup

- successful artifact history retains the full 500-step supported horizon
- consumed artifact hashes retain a wider bounded horizon
- newest 20 completed plans remain full; older completed plans compact heavy contexts/step text while preserving artifact receipts
- Diagnostics reports storage bytes, active/completed/compacted plans, artifact receipt count and retention policy
- `app/Extensions/**` is first-class throughout Titan specialized analyzers and all active Titan profiles set `includeExtensions: true`
- the original Mega Pack 1 agent prompt is archived and current docs no longer instruct agents to exclude extensions
- `src/titan-zero/pack.json` matches the actual production Titan import order; legacy `titan-zero-pack.js` stays historical/non-production
- Provider Registry owns ChatGPT/Claude conversation/composer/message selectors; generic “any textarea/contenteditable” fallback is removed
- provider adapter records are immutable; runtime dispatch uses the provider-neutral `sendPromptToProvider()` entry point

## Canonical release verification

`npm test` runs `node tools/verify-codee.mjs`, covering all top-level regressions, Titan donor suites, Repository donor suites, Workforce donor suite, JavaScript syntax, JSON parsing, Manifest V3 references, service-worker import references, active-source security sink scanning, and the package SHA-256 source manifest. `--zip <path>` additionally verifies ZIP integrity.

`source-manifest.json` records path, byte count and SHA-256 for every packaged file except the manifest itself and excluded build/archive artifacts.

## Authority invariants

- Codee core alone advances plans.
- Managers are advisory/delegating only.
- Repository/Titan intelligence does not directly mutate.
- MCP transport remains separately owned.
- Unknown/incomplete command or MCP effects fail closed.
- **No verified complete backup = no mutating execution.**
