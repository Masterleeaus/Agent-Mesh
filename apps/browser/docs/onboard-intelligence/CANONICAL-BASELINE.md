# Codee Browser Intelligence — Canonical Baseline

Pass 1 establishes the code-derived baseline for the browser-native onboard intelligence program against Titan Code v2.11.1.

## Direction

Codee's primary intelligence target is a shared in-browser runtime. Titan Bridge remains the governed desktop execution plane for repository, Git, commands, tests and filesystem operations. Ollama remains optional escalation, not a required dependency.

## Existing foundations to preserve

- Provider/request/response contracts and provider gateway.
- AI sanitization and audit foundations.
- Repository inventory/search/symbol/dependency/diff/impact/test/Git modules.
- Repository mutation, command, rollback and verification policy layers.
- Workforce task/capability/delegation/evidence/tool/verification contracts.
- Browser capability contract and exact-origin fail-closed policy model.
- MCP governance and inspector foundations.
- Multi-conversation plan concurrency restored in v2.11.1.

## Main convergence gaps

1. No shared browser-model inference host exists yet.
2. No unified `CodeeIntelligence` controller owns routing between models, memory, skills, tools and evidence.
3. No durable working, episodic or verified project-memory layer exists.
4. Existing skill catalogs are static data rather than a common versioned skill runtime.
5. No browser embedding/vector-memory runtime exists.
6. Repository intelligence is broad but fragmented and is not yet exposed as a unified RAG/evidence service.
7. Workforce intelligence is contract-rich but not yet converged with local memory/skills/model routing.
8. Browser execution remains contract/policy-first and must mature before autonomous browser action loops.

## Implementation rule

Future passes update `CANONICAL-BASELINE.json` rather than creating independent status authorities. Existing modules are extended first; parallel replacement architectures require explicit justification.
